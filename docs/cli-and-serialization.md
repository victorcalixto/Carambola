# CLI and Serialization

Carambola provides a command-line interface and JSON-based file formats for storing structural models and analysis results.

This allows a model to be:

1. created programmatically in Python,
2. saved to disk,
3. inspected from the command line,
4. solved without writing additional Python code,
5. and its results stored for later processing.

---

# Command-Line Interface

Installing Carambola provides the `carambola` command.

Check the available commands with:

```bash
carambola --help
```

The primary commands are:

```text
carambola inspect
carambola solve
```

---

## Inspect a Model

A `.carambola` model can be inspected with:

```bash
carambola inspect examples/cantilever_beam.carambola
```

The command reports the main contents of the model, including entities such as:

```text
Nodes
Trusses
Beams
Shells
Supports
Point loads
Uniform beam loads
Uniform shell pressures
```

For example:

```bash
carambola inspect examples/truss.carambola
```

can be used to inspect the truss model generated by:

```bash
python examples/truss.py
```

---

## Solve a Model

Solve a serialized model with:

```bash
carambola solve examples/cantilever_beam.carambola
```

By default, Carambola creates a corresponding result file.

For example:

```text
examples/cantilever_beam.carambola
```

produces:

```text
examples/cantilever_beam.carambola-result
```

---

## Specify an Output File

Use `-o` to specify the result path explicitly:

```bash
carambola solve \
    examples/cantilever_beam.carambola \
    -o analysis.carambola-result
```

The resulting file can then be inspected with:

```bash
carambola inspect analysis.carambola-result
```

---

# Model Serialization

Carambola uses the extension:

```text
.carambola
```

for serialized structural models.

The format is JSON-based and is intended to provide a transparent interchange format between:

- Python workflows
- the Carambola CLI
- computational design systems
- future Blender and Sverchok integrations
- other tools capable of reading and writing JSON

A `.carambola` file may contain:

```text
materials
sections
shell properties

nodes

trusses
beams
shells

supports

point loads
uniform beam loads
uniform shell pressures
```

The detailed format specification is documented in:

[`model-format.md`](model-format.md)

---

# Saving a Model from Python

A model can be saved with:

```python
import carambola as cb


model = cb.Model()

# Build model...

cb.save_model(
    model,
    "model.carambola",
)
```

The resulting file can immediately be inspected with:

```bash
carambola inspect model.carambola
```

or solved with:

```bash
carambola solve model.carambola
```

---

# Loading a Model from Python

Load a serialized model with:

```python
import carambola as cb


model = cb.load_model(
    "model.carambola"
)
```

The returned object is a normal Carambola `Model` and can be solved using:

```python
result = cb.LinearStaticSolver(
    model
).solve()
```

---

# Result Serialization

Linear-static results can be stored using:

```text
.carambola-result
```

Result files are also JSON-based.

They store the primary nodal solution:

- translations
- rotations
- reaction forces
- reaction moments

They also contain information used to verify compatibility with the corresponding model.

The detailed result format is documented in:

[`result-format.md`](result-format.md)

---

# Saving Results from Python

After solving a model:

```python
result = cb.LinearStaticSolver(
    model
).solve()
```

save the result with:

```python
cb.save_result(
    result,
    "analysis.carambola-result",
    model,
)
```

---

# Loading Results from Python

Load stored results with:

```python
stored_result = cb.load_result(
    "analysis.carambola-result",
    model,
)
```

Stored results are represented separately from the live C++ `AnalysisResult`.

This distinction is intentional.

A live `AnalysisResult` retains the information required for element-level FEM result recovery, while a serialized result represents the primary stored solution.

---

# Live and Stored Results

A live analysis result can provide element-level quantities such as:

```text
Truss3D
    deformation
    strain
    stress
    axial force

Beam3D
    axial force
    shear
    bending moment
    torsion

Shell3D
    membrane strain
    membrane stress
    bending curvature
    bending moments
    surface stresses
    von Mises stress
    principal stresses
```

For example:

```python
result = cb.LinearStaticSolver(
    model
).solve()

force = result.truss_force(
    model.truss(0)
)
```

or:

```python
stress = result.shell_top_stress(
    model.shell(0),
    1.0 / 3.0,
    1.0 / 3.0,
)
```

A stored `.carambola-result` file currently focuses on the primary nodal solution rather than reproducing the complete live `AnalysisResult` interface.

The examples included with Carambola can be used to demonstrate the complete workflow.

Run:

```bash
python examples/cantilever_beam.py
```

```text
examples/cantilever_beam.carambola
```

---

## 2. Inspect the Model

```bash
carambola inspect \
    examples/cantilever_beam.carambola
```

---

## 3. Solve from the CLI

```bash
carambola solve \
    examples/cantilever_beam.carambola
```

This produces:

```text
examples/cantilever_beam.carambola-result
```

## 4. Inspect the Result

```bash
carambola inspect \
```

# Python Workflow

The equivalent workflow can be performed entirely in Python:

```python
import carambola as cb


model = cb.load_model(
    "examples/cantilever_beam.carambola"
)

result = cb.LinearStaticSolver(
    model
).solve()

cb.save_result(
    result,
    "analysis.carambola-result",
    model,
)

stored_result = cb.load_result(
    "analysis.carambola-result",
    model,
)
```

This makes it possible to use the same Carambola model across interactive Python workflows, scripts, command-line analysis, and future computational-design integrations.

# File Extensions

Carambola currently uses two primary file extensions:

| Extension | Purpose |
|---|---|
| `.carambola` | Structural model |
| `.carambola-result` | Stored analysis result |

Both formats are JSON-based.

---

# Error Handling

The serialization API distinguishes malformed or incompatible Carambola files from general Python errors.

Model-format errors use:

```python
cb.CarambolaFormatError
```

Result-format errors use:

```python
cb.CarambolaResultFormatError
```

For example:

```python
try:
    model = cb.load_model(
        "model.carambola"
    )
except cb.CarambolaFormatError as error:
    print(error)
```

This allows applications integrating Carambola to handle invalid input explicitly.

---

# CLI Exit Codes

The Carambola CLI uses exit codes so it can be integrated into scripts, automated workflows, and CI systems.

Current exit codes are:

| Code | Meaning |
|---:|---|
| `0` | Success |
| `2` | Invalid input or unsupported extension |
| `3` | Missing or malformed input |
| `4` | FEM analysis failure |
| `5` | Output/write failure |

For example:

```bash
carambola solve model.carambola

echo $?
```

A successful analysis returns:

```text
0
```

# Computational Workflows

Serialization is intended to provide a boundary between the FEM kernel and higher-level computational design systems.

A future workflow may therefore look like:

```text
Blender / Sverchok
        │
        ▼
    Carambola
      Model
        │
        ▼
   .carambola
        │
        ▼
   FEM Solver
        │
        ▼
.carambola-result
        │
        ▼
visualisation / optimisation / design feedback
```

The same model representation can also be generated independently from Python or other software.

This separation is important for Carambola's goal of remaining a small, open and interoperable structural analysis toolkit.
